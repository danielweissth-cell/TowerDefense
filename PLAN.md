# План: Tower Defense «сквозь эпохи» для телефонов (UE 5.8)

> Статус: **планирование**. Код не пишем, пока пользователь не скажет начинать.
> Правила работы в [CLAUDE.md](CLAUDE.md), принятые решения в [DECISIONS.md](DECISIONS.md).

## 1. Что делаем

Короткая, но законченная игра Tower Defense (несколько уровней, 1–3 месяца) **для iOS и Android**.

- **Структура: три эпохи по три уровня** (всего 9 уровней): 1) средневековье, 2) наше время, 3) будущее.
  У каждой эпохи **свой набор башен** и врагов.
- **Стиль графики:** «игрушечная диорама».
- **Полностью бесплатная игра**: без рекламы, без покупок, без сбора данных. Выпуск в **Google Play и App Store**.
- **Тестовые телефоны:** Android и iPhone есть. Аккаунтов разработчика пока нет, купим ближе к выпуску.
- **Только одиночная игра**, мультиплеера нет.
- **Языки:** английский (основной) + русский.
- **Строить можно везде, кроме дороги** (сетка клеток, дорога и препятствия заняты).
- **Есть летающие враги**: летят своим маршрутом, по ним бьют не все башни.
- **Отличие от других TD:** игрушечная графика-диорама и путешествие через эпохи (раздел 2).

**Основной цикл:**
враги идут волнами по дороге (летающие по воздуху) → игрок ставит и улучшает башни за золото →
башни стреляют → убитые враги дают золото → дошедшие до замка отнимают жизни → пережил все волны = победа.

## 2. Дизайн игры (заполняем вместе)

> Этот раздел описывает, **во что** играем. Его надо заполнить до Этапа 5 (разнообразие контента).

### 2.1 Чем отличаемся
- **Графика: «игрушечная диорама».** Каждый уровень выглядит как настольный макет или игрушечный набор:
  яркие цвета, простые гладкие материалы, «пластиковые/деревянные» фигурки, мягкий свет, лёгкое
  размытие краёв (эффект tilt-shift). Этот стиль хорошо подходит телефонам: простые материалы
  и мало деталей работают быстро.
- **Структура: путешествие через три эпохи, в каждой три уровня и свой набор башен.**

| # | Эпоха | Оформление | Башни (идеи) | Враги (идеи) |
|---|---|---|---|---|
| 1 | Средневековье | Замки, деревни, лес | Лучники, баллиста, катапульта, маги | Рыцари, тараны, гарпии, дракон |
| 2 | Наше время | Город, военная база, порт | Пулемёт, миномёт, ПВО, снайпер | Пехота, джипы, танки, вертолёты |
| 3 | Будущее | Неон, роботы, купола | Лазер, плазма, тесла, щит | Дроны, мехи, киборги, корабль-матка |

Наборы башен и врагов эпох 2 и 3 пока черновые, детально обсуждаем перед Этапом 9.

Архитектурно эпоха описывается данными (`UTDEraData`): набор башен, врагов, оформление, музыка.
Добавить или поменять эпоху можно без изменения кода.

### 2.2 Башни, эпоха 1: средневековье (черновик)
| Башня | Роль | Бьёт по воздуху |
|---|---|---|
| Лучники | Базовая, быстрая стрельба | ✅ |
| Баллиста | Мощный выстрел по одной цели | ✅ |
| Катапульта / требушет | Урон по области | ❌ |
| Маги | Магический урон, игнорирует броню | ✅ |
| Смола / масло | Замедление + огонь | ❌ |
| Знамя / казарма | Поддержка соседних башен | — |

### 2.3 Враги, эпоха 1: средневековье (черновик)
| Враг | Особенность |
|---|---|
| Крестьянин-ополченец | Базовый |
| Разведчик на коне | Быстрый, мало HP |
| Латник | Броня против физического урона |
| Таран / осадная башня | Много HP, медленный |
| Летучие мыши / гарпии | **Летающие**, игнорируют дорогу |
| Дракон | **Летающий босс** |

### 2.4 Кривая сложности
Внутри эпохи 3 уровня:
- **Уровень 1:** знакомство с башнями эпохи, простые враги (в эпохе 1 ещё и обучение игре).
- **Уровень 2:** новые враги, первые летающие.
- **Уровень 3:** все враги эпохи + **босс эпохи** в последней волне.

Следующая эпоха открывается после прохождения уровня 3 предыдущей.
Каждая новая эпоха начинается немного сложнее, чем закончилась прошлая.

### 2.5 Порядок производства
Сначала **полностью делаем эпоху 1** (все механики + графика), затем эпохи 2 и 3 добавляются
как новые данные и ассеты на готовом движке игры.

## 3. Архитектура

### 3.1 Слои
| Слой | На чём | Что там |
|---|---|---|
| **Ядро (логика)** | C++ | Базовые классы и правила игры |
| **Контент** | Blueprints (наследники C++) | Модели, эффекты, звуки, визуальные мелочи |
| **Описание объектов** | Data Assets | «Что это»: меш, иконка, класс снаряда, имя/описание (`FText`) |
| **Баланс (цифры)** | Data Tables (импорт из CSV/таблиц) | «Сколько»: цена, урон, HP, скорость, состав волн |
| **Интерфейс** | UMG | Только показывает и отправляет команды |

### 3.2 Основные классы (C++)

**Режим и состояние**
- `ATDGameMode`: правила уровня: старт, победа, поражение.
- `ATDGameState`: золото, жизни, волна. Рассылает события (`OnGoldChanged`, `OnLivesChanged`, `OnWaveStarted`…).
- `ATDPlayerController`: ввод с тача (Enhanced Input), выбор/постройка/продажа башен.
- `ATDCameraPawn`: камера сверху: перетаскивание пальцем, щипок для зума, границы карты.
- `UTDCheatManager`: чит-команды для отладки (дать золото, пропустить волну, убить всех, неуязвимость).

**Враги**
- `ATDEnemyBase`: движение по сплайну без CharacterMovement.
- Наземные идут по **дороге** (`ATDPath`), летающие по **воздушному маршруту** (свой сплайн, на высоте).
- `UTDHealthComponent`: здоровье, получение урона, смерть.
- `UTDStatusEffectComponent`: замедление, горение, оглушение.

**Урон**
- Урон всегда передаётся структурой `FTDDamageInfo` (количество, тип урона, источник), а не просто числом.
- Типы урона и сопротивления описываются через **Gameplay Tags**: `Damage.Physical`, `Damage.Fire`, `Damage.Magic`.

**Башни**
- `ATDTowerBase`: поиск цели, поворот, стрельба, улучшения.
- Фильтр целей через Gameplay Tags: башня указывает, по кому может бить (`Enemy.Ground`, `Enemy.Air`).
- Стратегии выбора цели: First / Last / Strongest / Closest.
- `ATDProjectile`: стрела, ядро катапульты (по дуге), магический снаряд.

**Уровень и строительство**
- `ATDPath`: дорога (сплайн). `ATDAirRoute`: маршрут летающих.
- `UTDBuildGridSubsystem`: сетка клеток. Клетки под дорогой, препятствиями и башнями помечаются занятыми
  **автоматически** (по сплайну дороги и коллизии), руками отмечать ничего не нужно.
- `ATDCastle`: замок игрока, конечная точка.

**Системы (Subsystems)**
- `UTDWaveSubsystem` (World): волны, спавн по данным, таймеры.
- `UTDSpawnSubsystem` (World): **единая точка создания** врагов, снарядов, эффектов.
  Сначала просто создаёт объекты; пул добавляется внутрь, когда замеры на телефоне покажут нужду.
  Остальной код при этом не меняется.
- `UTDProgressSubsystem` (GameInstance): прогресс по эпохам и уровням, звёзды, настройки, язык. Сохранения с номером версии.

**Данные эпох и уровней**
- `UTDEraData`: эпоха: название (`FText`), список уровней, доступные башни и враги, музыка, оформление меню.
- `UTDLevelData`: уровень: карта, стартовое золото и жизни, волны.

### 3.3 Gameplay Tags (основа классификации)
```
Enemy.Ground / Enemy.Air / Enemy.Boss / Enemy.Armored
Damage.Physical / Damage.Fire / Damage.Magic
Status.Slowed / Status.Burning / Status.Stunned
Tower.Targeting.Ground / Tower.Targeting.Air
```
Новый тип врага или урона добавляется тэгом и данными, без новых `if` в коде.

### 3.4 Связи между системами
- Системы общаются через **делегаты (события)**, без жёстких ссылок друг на друга.
- UI только слушает события и отправляет команды контроллеру.

### 3.5 Особенности телефона (обязательно учитывать)
- **Управление пальцем:** тап = выбрать / поставить, перетаскивание = двигать камеру, щипок = зум.
  Превью башни с подсветкой клеток (зелёная можно, красная нельзя) и кнопка подтверждения
  (палец закрывает место, нужен явный «✓»).
- **Ориентация:** горизонтальная (landscape).
- **Интерфейс:** крупные кнопки (минимум ~44 pt), учёт «чёлки» и скруглённых углов (Safe Zone),
  масштабирование под разные экраны (DPI Scaling).
- **Производительность:** мобильный рендерер. Lumen и Nanite на телефонах не используем.
  Цель 60 FPS на средних телефонах (минимум 30). Цель по количеству: ~100 врагов на экране.
  Настройки качества (Scalability): низкое / среднее / высокое.
- **Жизненный цикл приложения:** при сворачивании игра **ставится на паузу и сохраняется**
  (телефон может закрыть приложение в любой момент).
- **Размер приложения:** следить за размером сборки (ограничения магазинов, лимиты на мобильный трафик).
- **Батарея и нагрев:** не держать лишний Tick, ограничивать FPS в меню.

### 3.6 Структура папок
```
Source/TowerDefense/
  Core/        GameMode, GameState, PlayerController, Camera, CheatManager
  Towers/      TowerBase, Projectile, Targeting
  Enemies/     EnemyBase
  Combat/      DamageInfo, Health, StatusEffects
  Level/       Path, AirRoute, Castle
  Systems/     Wave, Spawn, BuildGrid, Progress subsystems
  Data/        TowerData, EnemyData, WaveData, LevelData, строки Data Tables
  UI/          базовые C++ классы виджетов

Content/TD/
  Maps/ Towers/ Enemies/ Projectiles/ Data/ UI/ VFX/ Audio/ Materials/ Localization/ Environment/
```

## 4. Этапы работы

Каждый этап заканчивается **проверяемым результатом**. В скобках указано, чего на этапе **не** делаем.

### Этап 0. Подготовка окружения

- [ ] Установить Git LFS, настроить удалённый репозиторий на выбранном сервисе, `.gitignore` для UE.
- [x] Создать C++ проект `TowerDefense`, проверить сборку (собирается, 2026-10-16).
- [ ] Настройки проекта под телефоны (Mobile / Scalable, ориентация landscape, Android/iOS идентификаторы).
- [ ] Включить плагины: Enhanced Input, Niagara, Gameplay Tags.
- [x] Найден встроенный MCP-плагин Epic, клиент настроен (`.mcp.json`).
- [x] Включить плагин **Unreal MCP** + наборы инструментов (список в CLAUDE.md), автозапуск сервера.
- [x] Проверить подключение: Claude видит редактор через MCP (работает, 2026-10-16).
- [ ] Настроить локализацию: исходный язык English, культура `ru`, String Tables, шрифт с кириллицей.
- [ ] **Сборка «пустого» проекта на Android-телефон.** Проверяем, что цепочка сборки работает
      *до* того, как появится игра. Нужны Android Studio + SDK/NDK (версии в CLAUDE.md).
      Аккаунт для этого не нужен.
- [ ] **Сборка на iPhone** с бесплатным Apple ID (без платного аккаунта). Ограничение: сборка живёт
      на телефоне 7 дней, потом её надо поставить заново. Для тестов этого хватает.

### Этап 1. Серый прототип: враги идут по дороге
- [ ] Тестовая карта из кубов, камера с управлением пальцем (и мышью в редакторе).
- [ ] `ATDPath` + `ATDEnemyBase`, движение по дороге.
- [ ] `ATDCastle`: дошёл, значит минус жизнь.
- [ ] Отладочный HUD (жизни текстом), чит-менеджер.
- **Результат:** кубики-враги бегут по дороге и отнимают жизни. *(Нет башен, нет графики.)*

### Этап 2. Башни и бой
- [ ] `FTDDamageInfo`, `UTDHealthComponent`, `ATDTowerBase`, `ATDProjectile`.
- [ ] Gameplay Tags для урона и врагов.
- [ ] Поиск цели, поворот, стрельба, смерть врага.
- [ ] Первые данные: 1 башня, 1 враг (Data Asset + строка Data Table).
- [ ] Отладка: показ радиуса башни.
- **Результат:** башня, поставленная в редакторе, убивает врагов. *(Нет постройки игроком.)*

### Этап 3. Сетка, строительство и экономика
- [ ] `UTDBuildGridSubsystem`: сетка, автоматическая блокировка дороги.
- [ ] Постройка пальцем: превью, подсветка клеток, подтверждение, проверка денег.
- [ ] Золото, награда за убийство, продажа и улучшение башни.
- [ ] Отладочный HUD: золото.
- **Результат:** игрок сам строит башни где угодно, кроме дороги.

### Этап 4. Волны, победа и поражение ✅ Главная веха
- [ ] `UTDWaveSubsystem` + данные волн.
- [ ] Кнопка «следующая волна», таймер между волнами.
- [ ] Победа и поражение.
- [ ] **Проверка на реальном телефоне** (FPS, управление).
- **Результат:** полный игровой цикл одного уровня на телефоне.

### Этап 5. Разнообразие (по разделу 2 «Дизайн игры»)
- [ ] Летающие враги + воздушные маршруты, фильтр целей башен (земля/воздух).
- [ ] 5–6 башен, 5–6 врагов, статус-эффекты, броня и сопротивления.
- [ ] Стратегии выбора цели.

### Этап 6. Интерфейс

## 5. Как работаем
1. Перед каждым этапом уточняем детали, Claude пишет короткий план этапа.
2. Claude пишет C++ код и через MCP настраивает редактор, пошагово объясняя, что происходит.
3. Пользователь проверяет в игре, коммитим, идём дальше.
4. Не переходим к следующему этапу, пока текущий не работает.
